# PT6: Classify generated roadmap artifacts correctly in CI

**Existing prompt scope:** P651, proportionate executable validation.

**Status:** ready-for-agent for this owner-directed tooling repair; catalog completion is unchanged.

**Planning source:** [Approved proof-tooling repairs](../PRODUCT_MILESTONES.md#approved-proof-tooling-repair-tickets--2026-10-16).

**What to build:** A publication that changes only the prompt catalog, planning documents and their generated roadmap artifacts runs the relevant consistency checks without being classified as an unknown application change.

**Blocked by:** None (can start immediately).

## Acceptance criteria

- [ ] Reproduce the inspected publication's classification: the deployment selector recognizes its generated artifacts as tooling and selects no application targets, while CI's risk classifier selects the full application suite.
- [ ] Recognize only the established generated roadmap artifact paths and retain catalog, generated-view, dependency and documentation checks appropriate to those changes.
- [ ] Apply the same classification through normal candidate CI and the exact-main verification path; retain their source binding and existing release behavior.
- [ ] A mixed change containing application, callable, rules, workflow or other actual behavior changes retains all checks required by that risk. Unrecognized files continue to receive the conservative fallback.
- [ ] Focused classification and workflow-consumer regressions fail on the original mismatch and pass after repair, including negative controls for mixed and unknown changes.

## Testing and handoff boundary

Observe meaningful classification RED before implementation. Extend existing classifier and workflow-contract tests, then inspect the resulting check selection for the retained documentation-only publication and representative mixed changes. Preserve meaningful application tests and existing budgets.
