## Transaction behavior

Successful manual location moves, ordinary jumps, emergency jumps, and facilitator-adjudicated jumps now include a docked Voyage coordinate update in the same Firestore session transaction as the host movement. The update increments Voyage's movement revision so commands captured before the host departure become stale. It preserves the existing Voyage Jump Drive state and leaves Voyage maintenance, host assignment, and docking revision unchanged.

A valid Voyage docked to a different active host receives no movement patch. A malformed admission or movement record, malformed or inactive docking host, destroyed host being moved, invalid destination, or exhausted Voyage movement revision fails the transaction before the movement commits. Failed or stale host actions do not move Voyage. Exact host-command replay returns its existing receipt before movement synchronization, so a later Voyage independent jump and redock cannot be overwritten. Voyage's own jump callable remains responsible for its separate FTL movement and for clearing the docked host.

The accepted split-fleet audience contract keeps another group's location private (`docs/IMPLEMENTATION_CONTRACTS.md`, Redaction invariants, and PC06-A6/A14 in `docs/PRODUCT_MILESTONE_ASSUMPTIONS.md`). The complete Voyage coordinate is now server-only in `sessions/{id}/serverState/voyage33Movement`; it is absent from the member-readable session and from ordinary `joinSession`/`resumeSession` replies. A connected GM retains access to a legacy header only long enough for an authorized backend transaction to validate and migrate it. The rules deny member header reads while that legacy field remains, direct reads of the private canonical document, member reads of `gmDiscovery/current`, all client writes, and collection enumeration.

`resolveVoyage33MovementStorage` accepts a valid private record, a valid legacy record awaiting migration, or an identical pair during migration. It rejects malformed or divergent copies before a transaction writes. Join/resume resolve the current actor, connection, and membership first, then compose the existing complete GM navigation view, write the private canonical state, and delete the member header in the same transaction; their returned session projection omits Voyage coordinates. The normal dock/jump callables and all four host-movement paths read private and legacy state in their initial transaction read phase and atomically write the private canonical state, update only the Voyage-owned fields of `gmDiscovery/current`, and clear the legacy header. Each host-movement path also preloads its Wolf-arrival state before any transaction write; the writer consumes that snapshot and performs no late read. A new transaction-trace test covers manual, ordinary, emergency, and adjudicated movement. It exposed an older read-after-write sequence: jump damage could write a press-log entry before emergency or adjudicated movement read the Wolf-arrival state. The same sequence is present in the f27 baseline's `jumpDamageConsequences` and `writeWolfArrivalPressureForMovement` flow, so this is a pre-existing Firestore transaction-order defect revealed by the scoped regression, not a side effect of the private Voyage field.

All GM discovery writers were audited. Navigation rebuilds use explicit owned-field masks; start-game, pursuit-window, and ECM partial writes own only their named fields. These updates preserve Voyage authority and do not retain a stale cache as current. Newly created sessions initialize the complete navigation projection without a Voyage movement record. A Voyage-only write uses `mergeFields` for its movement, session tag, and timestamp, so it preserves the existing navigation and knowledge fields.

The GM workspace accepts Voyage movement only from the current server-backed `gmDiscovery/current` document whose session tag matches. The listener clears its projection for cached snapshots, missing or malformed documents, session mismatches, and denied reads. The store accepts the value only while the current session identity, live server snapshot, GM role, and named current GM claim agree; identity, claim, role, connection, session, and stale-snapshot loss clear the movement and readiness. A fresh complete GM navigation view with no Voyage state remains a valid empty projection for first docking. The workspace keeps movement actions unavailable until it receives that private view, and routine public session-header updates cannot replace the accepted coordinate. This retains the existing Voyage action authorization and UI behavior while enforcing the accepted A6/A14 audience boundary; it does not add player movement entitlements or broaden PC07.
