# Approved execution refinements

The October 28 owner-approved breakdown covers 97 open execution briefs as 260 bounded units. It adds 237 child issues and reuses 23 already atomic issues. The original 48 PC10 prompt acceptances and the fixed 751-prompt endpoint remain unchanged.

These are refinements of existing scope. GitHub holds mutable tracking state; the linked source files hold behavior definitions. The publication mapping records identities and dependency references only. It does not introduce a second status catalog or rewrite the immutable migration crosswalk.

The 32 held future source briefs and all their descendants retain their original phase/trigger and remain inactive. The PC10 gameplay pause, checkpoint release boundaries, restricted-version permissions and accepted evidence stay in force.

Atomic actions keep permission, payment, committed result and retry checks together. Every new behavior is a complete action-to-result or real consumer path. No schema/API/UI-only work queue is introduced. Full-game stages preserve the same actual session; C4/H1/H2/V2 reuse the same expansion actions instead of requiring duplicate games.

## Original gates and narrower leaf edges

Every source brief retains its original native blocker relationships and any documented equivalent edges. New children name precise additional leaf dependencies. Child completion never waives a parent prerequisite or original acceptance. The 23 reused issues retain their existing native blockers without modification; their rows below show the bounded execution handoff inside those unchanged source gates.

## Tracking and later hold release

The original migrated prompts and briefs continue to use the existing tracker writer. These refinements are native child issues, not new migration records; track each child on its GitHub issue without changing the immutable migration crosswalk. A future hold release first satisfies the original parent trigger through its existing reviewed release path, then deliberately updates the affected children under that authorization. Publication does not release a hold or make a paused action executable.

A parent is accepted only after its entire original acceptance and all applicable children are satisfied. The publication mapping records original identities and expected relationships, not current mutable completion or readiness.
