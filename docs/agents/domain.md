# Domain docs

Use a single-context layout: root `GLOSSARY.md` and `docs/adr/`.
Read the glossary and relevant ADRs when present before domain work. Create them
lazily when a term is resolved or a consequential trade-off warrants an ADR.
Their absence is not a blocker. Use the glossary's terms consistently and surface
conflicts with existing ADRs before changing the decision.

The prompt catalog remains the roadmap authority; checkpoint plans and owner
feedback retain their existing roles. Domain documentation does not replace them.
